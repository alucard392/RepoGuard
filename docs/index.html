RepoGuard

Catch likely leaked credentials, sensitive files, oversized files and missing repository basics before you commit or push.

Get startedSecurity boundariesProject policies

Designed to stay local

RepoGuard scans your working tree or staged Git blobs on your machine. It does not upload source code, make network requests, send telemetry, or automatically modify files. Findings are redacted.

Secret patterns

Recognizes GitHub, AWS, OpenAI, Google API, Stripe, Slack, Azure, GCP, DigitalOcean, Heroku secret token formats, PEM/OpenSSH/EC private keys, database connection strings, and suspicious generic/high-entropy assignments.

Repository hygiene

Checks sensitive filenames (Docker, Kubernetes, AWS, Terraform, backups), large files, missing .gitignore/README/license and basic project metadata.

Two interfaces

Use the command line for automation or the Tkinter desktop GUI for interactive review.

Get started

Install from a source checkout, then launch the GUI or scan from a terminal.

python -m pip install .
python -m repoguard gui
python -m repoguard scan .
python -m repoguard scan --staged .
python -m repoguard scan --verbose .
python -m repoguard scan --quiet --format json .
python -m repoguard scan --summary-only --format json .

Staged scans require Git. They read the Git index, not later unstaged edits.

Honest security boundaries

Secret detection is heuristic, not a guarantee. Obfuscated or split secrets can be missed, and generic rules can produce false positives. A clean scan is not a security certification. If a real credential may have leaked, revoke or rotate it immediately.

Project policies

The repository includes a security policy, contribution guide, code of conduct, support guidance and MIT license. Private vulnerability reporting, branch protection, secret scanning and Dependabot must be enabled by maintainers in GitHub settings; documentation does not enable them automatically.
